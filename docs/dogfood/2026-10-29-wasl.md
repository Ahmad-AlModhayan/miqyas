# Dogfood: Miqyas phase 1 on Wasl (2026-10-29)

## Setup

- App under test: the Wasl tray window, `desktop/` of the Wasl commit TestSprite was measured on (mock fixes included), exported read-only with
  `git archive` into a scratch folder. The Wasl repository and the user's installed Wasl were
  not touched.
- Build: `npm ci`, then `NODE_ENV=development vite build --mode development --outDir dist-mock` (what
  `npm run build:mock` does; its POSIX env syntax doesn't run under Windows cmd). 169 KB JS + 19 KB mock chunk +
  71 KB CSS.
- Served with `vite preview --outDir dist-mock --port 4173 --strictPort` (= `npm run preview:mock`).
- Plans: the 11 TestSprite plans of `desktop/testsprite/plans/`, imported with
  `miqyas import testsprite … --out plans/wasl`.

58 replacements in 2 files; Miqyas's re-scan and ripgrep both find 0. **New finding:** the CSS bundle names other
Kahf products too (`--kf-product-mizwala…`, `--kf-product-qasd…`, `.kf-scope-mizwala`: design-system colour
tokens copied from `kahf.css`). The TestSprite-era scrub covered `assets/*.js` only, so these left in the CSS then.
Renaming them is harmless here (Wasl doesn't use those scopes). Scrub whole builds, not just JS.

## Plans

`miqyas lint`: 11 plans, 0 errors. **34 assertions**, not 32: the evaluation's total is a miscount (its own per-plan
column sums to 34), so TestSprite's record covered 17 of 34.

## Dry run (no model)

`miqyas run plans/wasl --url http://localhost:4173/ --dry-run`: exit 0; all 11 plans resolve; each page observed with
113 rendered nodes (cards, states, bidi-isolated paths). The first attempt observed only 23 nodes: the mock shows
"Connecting to Wasl's background service…" for about a second, and a fixed 400 ms settle caught that screen. Fixed:
after a load the runner waits for network idle and 1.2 s without DOM mutations (cap 6 s).

## Mutations (no model)

`miqyas mutate plans/wasl --build dist-mock --preset wasl-tray --dry-run`: all four apply to copies and are
confirmed effective by code probes:

| Mutation | Probe on clean → mutated |
|---|---|
| bin-text | 1 occurrence swapped; build served |
| field-error-hidden | `.field-error` display `block` → `none` |
| passphrase-error-hidden | `.kf-field-error .kf-field-help` display `flex` → `none` |
| rtl-flip | `body` direction under `dir=rtl`: `rtl` → `ltr` |

Then each targeted flow was driven by code (no model) on the clean and the mutated build, to check that what Miqyas
hands its judge actually differs:

| Plan / assertion | Clean build observation | Mutated build observation |
|---|---|---|
| 03 a2 (error list) | `alert "Choose a folder on this computer. Choose a folder on Drive. Give the pair a name."` | no alert in the snapshot (`.field-error` still in the DOM): the case TestSprite passed |
| 06 a2 (wrong passphrase) | `text "Wrong passphrase for this vault."` | absent from the snapshot |
| 07 a1 (Arabic) | `dir=rtl lang=ar`, navigation "الأقسام" at x=1056 of 1280 | `dir=rtl lang=ar`, navigation at x=0 |
| 01 a7 (bin text) | string present in the bundle | swapped in the bundle |

**Runner bug found and fixed:** Wasl's language choice is a radio input under a chip `<label>` that intercepts the
pointer; clicking the radio timed out. The runner now clicks the covering label (regression test in
`test/e2e/runner.test.ts`).

## Live run: blocked on the key

`ANTHROPIC_API_KEY` is not set in this environment, so the 11 plans have not been judged by a model and the mutation
run has no detection rate yet. To finish, with the key set in your own shell and the scrubbed build served on :4173:

```bash
node dist/cli.js run plans/wasl --url http://localhost:4173/ --scrub wasl-scrub
node dist/cli.js mutate plans/wasl --build <desktop>/dist-mock --preset wasl-tray --scrub wasl-scrub
```

Only screenshots and snapshot text of the scrubbed build go to Anthropic's API; `payloads.jsonl` in the run folder
lists every call.

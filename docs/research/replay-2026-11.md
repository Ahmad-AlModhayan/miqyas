# Record and replay of model calls: prior art and a cassette key for Miqyas

Research for ticket 30 (part of map ticket 26), 2026-11-03. Sources are primary: official docs and the Miqyas source at
`88cad7b`. No model calls were made.

## The question

You can't choose a mock or replay agent from the CLI (`src/cli.ts:115-133`; `makeAgent` builds `AnthropicAgent` unless a
test injects one). So the only way to measure detection is to spend money on the API. This note covers three things:

- how VCR-style tools and LLM eval harnesses key, store, match and invalidate recordings, and what they do on a miss;
- what a Miqyas model request is made of, and which parts change from run to run;
- a recommended cassette design: the key, the storage, miss behaviour, screenshot handling, and the risks.

## 1. Prior art

### Polly.js (Netflix)
Source: [docs/configuration.md](https://github.com/Netflix/pollyjs/blob/master/docs/configuration.md).

- **Modes.** `replay` is the default. `record` "will overwrite recordings that already exist". `passthrough` neither records nor replays.
- **On a miss.** `recordIfMissing` defaults to `true`: "If a request's recording is not found, pass-through to the server and record the response". In other words, Polly fails *open* by default.
- **Key.** `matchRequestsBy` defaults to method, headers, body, **order**, and every URL part except `hash`. Each part can be turned off, or normalised with a function.
- **Repeats.** With `order: true`, identical requests are told apart by their occurrence index.
- **Expiry.** `expiresIn` sets an age. `expiryStrategy` is one of `warn` (the default), `error` or `record`.
- **Failed calls.** `recordFailedRequests: false` throws rather than persist a failed request.

### nock back
Source: [nock README, "Nock Back"](https://github.com/nock/nock#nock-back).

- **Fixtures.** One JSON fixture per test. Each entry holds `scope`, `method`, `path`, `body`, `status`, `response` and `rawHeaders`. Request headers are recorded only when `enable_reqheaders_recording` is set.
- **Modes.** Set with `NOCK_BACK_MODE`:
  - `wild`: everything goes live.
  - `dryrun`, the **default**: replay, and allow real calls.
  - `record`: replay, and record new calls.
  - `update`: delete the fixture and re-record.
  - `lockdown`: replay, and disable all unmocked HTTP.
- **Fail closed only on request.** Only `lockdown` fails closed, and you have to choose it.
- **Matching.** Playback uses nock's ordinary interceptor matching on scope, path and body. The README shows the fields but does not spell out the algorithm.

### VCR.py
Sources: [usage](https://vcrpy.readthedocs.io/en/latest/usage.html), [configuration](https://vcrpy.readthedocs.io/en/latest/configuration.html), [advanced](https://vcrpy.readthedocs.io/en/latest/advanced.html).

- **Record modes.**
  - `once`, the default: record if there is no cassette, otherwise "Cause an error to be raised for new requests if there is a cassette file".
  - `none`: replay only, and raise on any new request.
  - `new_episodes`: replay, and record anything new.
  - `all`: always record, never replay.
- **Fail closed by default.** Once a cassette exists, VCR.py fails closed, which is the opposite of Polly and nock.
- **Key.** The default `match_on` is method, scheme, host, port, path and query. The body is not in the default key.
- **Custom matchers.** You can add your own with `register_matcher`, as a function over two requests that asserts or returns a bool.
- **Scrubbing.** Volatile or secret parts are removed before storage with `filter_headers`, `filter_post_data_parameters` and `before_record_request` / `before_record_response`. Returning `None` drops an interaction.
- **Playback once.** By default "each response in a cassette can only be matched and played back once". To allow repeats, set `allow_playback_repeats=True`.
- **Format.** YAML by default, or JSON with `serializer='json'`.

### Playwright HAR replay
Sources: [`browserContext.routeFromHAR`](https://playwright.dev/docs/api/class-browsercontext#browser-context-route-from-har), [Mock APIs guide](https://playwright.dev/docs/mock).

- **Matching.** Replay "matches URL and HTTP method strictly", and POST bodies must match too. When several entries match, "the one with the most matching headers is picked". This is a near-match tie-break, used only *after* the strict key has matched.
- **On a miss.** `notFound: 'abort'` is the default and fails closed. `'fallback'` passes the request to the next handler.
- **Recording.** `update: true` re-records from live traffic and writes when the context closes. `updateMode: 'minimal'` is the default and keeps only what routing needs. `updateContent: 'embed' | 'attach'` sets whether bodies sit inline or as side files.
- **In version control.** The guide expects the HAR to be committed with the tests and allows editing it by hand.

### Replaying LLM calls (first party)

- **Inspect (UK AISI), [Caching](https://inspect.aisi.org.uk/caching.html).** This is the closest prior art.
  - **Key.** Model name and base URL, the full message history, the epoch, the generate config (temperature and so on), and the active `tools` / `tool_choice`. Optional named `scopes` can be added.
  - **Expiry and switch.** Entries expire after one week by default. Caching is off unless `--cache` is given.
  - **Two caveats that apply to Miqyas.** First, model *aliases* can move to a new version while the cache keeps serving the old one, so key on a pinned version. Second, a cache suits development, "such as iterating on a scorer", rather than final results.
- **promptfoo, [Caching](https://www.promptfoo.dev/docs/configuration/caching/).**
  - **Key.** A composite of the provider id, a digest of the prompt, the provider config and variables.
  - **Storage and expiry.** Stored on disk at `~/.promptfoo/cache` with a 14-day TTL.
  - **What is cached.** Only successful responses. Errors and empty replies are never cached.
  - **Switch.** Off with `--no-cache`.
- **Anthropic SDK (TypeScript), [CONTRIBUTING.md](https://github.com/anthropics/anthropic-sdk-typescript/blob/main/CONTRIBUTING.md).** The SDK's own tests run against a mock server generated from the OpenAPI spec (`./scripts/mock`). That mock returns schema-shaped data, not recorded model behaviour. The SDK offers users no record or replay helper. Miqyas already has the seam it needs: `AnthropicAgentOptions.client`, plus the `Agent` interface itself.

### What the prior art agrees on
1. **Key on the request, not on the test.** Every tool here keys on request content: URL, method, body or messages. Each one lets you normalise or filter the volatile parts before matching.
2. **Tell identical requests apart.** Polly uses `order`. VCR.py plays each response back once.
3. **Miss behaviour is split.**
   - Polly and nock fail open (they go live).
   - VCR.py `once`/`none`, Playwright's `abort` and nock's `lockdown` fail closed.
   - The fail-closed tools are the ones designed to stop *unexpected* traffic, which is Miqyas's concern: money and confidential pages.
4. **Invalidation is either content-addressed or time-based.** Content-addressed means a changed request misses. Time-based means a TTL (Polly, Inspect, promptfoo). The LLM harnesses put the model and its config in the key, so a model change misses on its own.
5. **Don't store failures.** promptfoo doesn't cache them, and Polly throws by default.

## 2. What a Miqyas request is made of

Every call goes through `AnthropicAgent.call` (`src/model/anthropic.ts:163-192`). It calls `gateCall` first, which re-scans the text and logs it to `payloads.jsonl`. It then sends this request:

| Part | Source | Run-to-run stable? |
|---|---|---|
| `model`, `max_tokens`, `output_config.effort`, `betas`, `fallbacks` | `info`, constants | Stable within a configuration |
| `system` | `ACT_SYSTEM` / `JUDGE_SYSTEM` | Stable; changes when the prompt is edited |
| `tools` | `ACT_TOOLS` / `JUDGE_TOOLS` | Stable; changes when the code is edited |
| First user message | Plan name, step history (`historyText`), step id and text | Mostly stable, but the history embeds the *results* of earlier steps (the model's own summaries) |
| Snapshot text (`captureBlocks` → `snapshotText`, `src/web/observe.ts:277`) | One line per node: `ref role "name" [state] @x,y wxh`, plus a header line | **Volatile in parts**, listed below |
| Screenshot (`imageBlock`) | A base64 PNG, cropped to 3000 px | **Volatile.** Not scrubbed (`images.scrubbed: false`), with font and antialiasing differences between macOS and Windows |
| Later turns | The assistant's `tool_use` blocks and the user's `tool_result` blocks, each with a fresh capture | `tool_use.id` values are server-generated |

The volatile parts of the snapshot text are these:

- **The capture number and every ref.** Both come from a process-global counter (`captureCounter`, `observe.ts:240-243`; refs are `c<capture>e<n>`). With `--concurrency 3`, plans interleave, so the same page gets different numbers from run to run.
- **The origin.** The served build listens on port 0 (`src/web/server.ts:31,61`). The header's `http://127.0.0.1:<port>/` therefore changes on every run.
- **Elapsed time in the judge prompt.** "(`x.x` s before the current one)" (`anthropic.ts:258`).
- **Boxes.** Usually stable on one machine with a fixed viewport (`DEFAULT_VIEWPORT`). They can differ by a pixel or so across operating systems, because of fonts.
- **Tool-use ids.** The `toolu_…` ids in later turns are random per live call. On replay they come from the cassette, so they stay consistent within a replay.

The `at` timestamp is in the log entry only, not in the request.

## 3. Recommendation for Miqyas

### The agent
- **A `ReplayAgent`.** Add a `ReplayAgent implements Agent`, rather than an HTTP-level mock. It wraps the same request building, so the key covers exactly what would have been sent. The cleanest seam is the inner `call()`: record and replay at the `beta.messages.create` boundary, through the existing `client` option or a small `Transport` interface. The tool loop, `gateCall` and the logging then still run unchanged. The replay path needs no credentials.
- **CLI flags.**
  - `--record <cassette>`: run live and write the cassette.
  - `--replay <cassette>`: replay only.
  - `--replay <cassette> --live-on-miss`: the explicit escape hatch.
  - No mode is ever implicit.

### The key
The key is `sha256(canonical JSON of the normalised request)`, with these parts:

- **Configuration.** `cassetteSchema`, `normaliserVersion`, `provider`, `model`, `effort`, `max_tokens`, `betas`, `fallbacks`.
- **The full `system` and `tools`.** A prompt or tool edit then misses on its own, as in Inspect.
- **The full `messages` array, after these normalisations:**
  - Rename refs **positionally per request**: the first `c\d+e\d+` seen becomes `r1`, the next distinct one `r2`, and so on. This applies to the snapshot lines, to the refs inside earlier `tool_use` inputs and to `evidence_refs`. Drop `capture N` numbers in the same pass.
  - Replace `http://127.0.0.1:<port>` with `$ORIGIN`.
  - Remove the `(x.x s before …)` elapsed time, or round it to a bucket.
  - Rename `tool_use.id` / `tool_use_id` positionally (`t1`, `t2`, …).
  - Replace every image block with `{type:'image', ref:'img<k>'}`. The bytes stay **out** of the key (see Screenshots).
- **An occurrence index.** Repeated identical requests are replayed in recorded order (Polly `order`, VCR playback-once). A repeat beyond what was recorded is a miss.
- **Boxes stay in the key.** A layout change is a page change, and that is what Miqyas exists to detect. Cross-OS replay may therefore miss more often. Treat a cassette as tied to one OS and say so in its header.

**Rejected: a semantic key (plan + step + turn + snapshot-text hash).** It is weaker. Changing a prompt or tool would not invalidate it, and in multi-turn act loops it can't see the model's own earlier turns. The positional-normalised full request covers plan, step and snapshot anyway.

### Storage
- **Format.** `cassette.jsonl`, written in the run directory beside `payloads.jsonl` (`makeAgent`, `cli.ts:127`). It starts with one header line, then one line per call.
- **Header line.** Schema version, Miqyas version, model, effort, OS, viewport, and the app commit or build hash when known (bench runs pin a commit). It also records the sha256 of the scrub rules, already reported in the method block.
- **Call lines.** Each line holds:
  - `key` and `occurrence`;
  - `kind`, `planId`, `stepId`, `turn`;
  - the normalised request *text* (already scrubbed; the same text `payloads.jsonl` logs), so a miss can be diffed;
  - per image: `sha256` and a 64-bit `dHash`;
  - the response: `content`, `stop_reason`, `usage`, and the response's own `model` field (it can differ under server-side fallback; and see Inspect's alias caveat).
- **What is never stored.** Image bytes, which are unscrubbed page pixels. Failed calls (API errors, `refusal`, `max_tokens`), following promptfoo and Polly.
- **Scrub check.** Response text is re-scanned with `rescan` before it is written.
- **Promotion.** A cassette worth keeping is copied from the run directory to a stable path, for example `bench/<name>/cassettes/<plan>.jsonl`. Replay always takes an explicit path.

### Miss behaviour
- **Fail closed by default** (VCR `none`, Playwright `abort`, nock `lockdown`). A miss raises a `ReplayMiss` error: the plan ends as an error (exit 3), never as a pass or fail. The message names the key, the plan, step and turn, and a short text diff against the closest recorded request for the same plan and step, so a stale cassette is obvious.
- **`--live-on-miss`.** Only this flag makes a live call. It needs credentials, and the call is appended to a *new* cassette, never the one being read.
- **The report says how the run was made.** `method.model.replay = { cassette, cassetteSha256, hits, misses, liveCalls, imageMismatches }`. A run with any live call is marked mixed.

### Screenshots
- **Exclude image bytes from the key.** The PNG bytes change on font, antialiasing and timing noise. Keying on them would make every replay miss, especially between the Mac and the PC.
- **But verify them, because an excluded screenshot is the main false-detection risk.** The snapshot text does not capture a visual-only mutation: colour, an image, CSS that changes appearance but not role, name or box. Such a mutant gets a text-key hit and replays the clean build's "pass". The mutant then counts as *missed* when the live judge might have caught it. That lowers the detection score falsely.
- **On every hit, compare the current screenshots with the recorded ones:**
  - `sha256` equal: a clean hit.
  - `sha256` differs but the dHash Hamming distance is ≤ a small threshold (to be calibrated on clean-vs-clean reruns): a **near-hit**. It replays, and it is counted in `imageMismatches`.
  - The dHash differs beyond the threshold: a miss.
- **Scored runs need no near-hits.** A detection score is published only from a live run, or from a replay with `imageMismatches = 0`. Inspect's own caveat is that caches suit development, not final results.

### Risks
1. **A stale verdict gives a false detection score.** This is the main risk, and the cause is a visual-only change. Mitigations: the image check above, the app commit in the header, and "replayed" written in the report.
2. **A cassette recorded on the clean build is replayed against mutants.** Every mutant that changes the snapshot misses, which is the correct, fail-closed outcome. So replaying a mutation sweep needs a cassette recorded *per mutant*. Replay saves money only on re-runs of the same pinned build and mutants, which is exactly the development loop.
3. **Model aliases and fallback.** Store the response `model`. Keying on a moving alias replays the old model's behaviour (Inspect's warning).
4. **Positional renaming can collide.** It could map two genuinely different pages to the same key only if their whole text is identical apart from ref numbers. That is the same page, so it is safe.
5. **Privacy.** Cassettes hold scrubbed text and model replies, and no pixels. They may be committed for bench apps, but not for confidential apps: put them under the run directory and keep them in `.gitignore` by default.
6. **Order and concurrency.** Occurrence indices are per key. Keys include the plan and step text, so concurrent plans don't steal each other's entries.
7. **Cross-OS boxes.** Expect misses when a cassette recorded on macOS is replayed on Windows. Record one cassette per OS, or later add an opt-in box tolerance (`@x,y` rounded to 4 px) that counts as a near-hit, never a hit.

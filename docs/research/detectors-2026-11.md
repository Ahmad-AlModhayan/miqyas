# Code-checkable detectors per category in Playwright/Chromium

Research for ticket 31 (map: ticket 26). Date: 2026-11-03. Playwright 1.64.1, Chromium. No model calls; sources are official docs, specs and source code, cited as [n].

**Question.** For each category Miqyas should cover (functional, security, UI/UX, accessibility), what deterministic check runs in Playwright/Chromium with no model, and what does each cost (dependency, runtime, licence), how often does it lie, and how hard is it to wire into `src/web/observe.ts` / `src/web/runner.ts`?

**Starting point in the code.** `observe.ts` builds its own snapshot in the page: `roleOf` (48-62) maps a fixed tag table plus `role=`, `nameOf` (64-81) is a partial accessible-name computation (aria-label, aria-labelledby, `labels[0]`, alt, placeholder, else innerText cut at 120), `stateOf` (87-105) has no focus. `runner.ts:97-108` (`runCheck`) supports only `visible`, `hidden`, `count`, `text` on a locator. No `console`, `pageerror` or `requestfailed` listener exists anywhere in `src/web/` (grep). `src/core/scrub.ts` and `runner.ts`'s `hide` already know the run's configured secret values.

## 1. Detectors by category

### Functional

- **Console errors and uncaught exceptions.** `page.on('console')` / `page.on('pageerror')` ("Emitted when an uncaught exception happens within the page"), or after the fact `page.consoleMessages()` and `page.pageErrors()`, each returning "up to (currently) 200 last" items [1]. No dependency, ~zero runtime. False positives: third-party script noise and deliberate `console.error`; an allowlist by URL/text keeps it honest.
- **Failed requests.** `page.on('requestfailed')` fires only when "the client cannot get an HTTP response", e.g. `net::ERR_FAILED`; "HTTP Error responses, such as 404 or 503, are still successful responses from HTTP standpoint" [1]. So two signals are needed: `requestfailed` plus `response` with `status() >= 400`. `page.requests()` exists but keeps limited information [1]. Risk: expected 401/404 (probes, analytics blocked by an ad blocker); report, don't fail.

### Security

- **XSS, sink tracing (Trusted Types report-only).** Serve the page with `Content-Security-Policy-Report-Only: require-trusted-types-for 'script'`. With disposition *report*, the string assignment proceeds unchanged [4 §2.3.5], and every string reaching a DOM XSS sink (`innerHTML`, `eval`, `script.src`, …) produces a violation whose sample is the sink name and the first 40 characters of the value [4 §4.2.4]. The CSP3 "report a violation" algorithm fires a `securitypolicyviolation` event regardless of disposition [5 §5.5], so an init script (`addInitScript` [1]) can collect them. The header cannot be set from a `<meta>` tag [5 §3.3][6], so it must be injected by `page.route` + `route.fetch` + `route.fulfill` with an extra header; "Enabling routing disables http cache" [1], and service-worker-served requests are not intercepted [1]. Cost: no dependency, slower loads (no cache). False positives: high as a *bug* signal on its own: every `innerHTML = '<b>static</b>'` reports. It is a map of sinks, not proof of XSS. It becomes precise when combined with the next item: a violation whose 40-char sample contains Miqyas's own marker is a tainted flow.
- **XSS, payload reflection.** Type a unique, inert marker (e.g. `mqy7x<i>"'`) into inputs/URL params, then check (a) the DOM for an element actually created from it (`document.querySelector('i')` inside the reflected text's container, or a TT violation sample containing `mqy7x`), and (b) raw response bodies containing the unescaped marker. Needs actions on the page, so it needs a plan step (or a crawler). Near-zero false positives when the check is "markup parsed", not "string echoed". No dependency.
- **Open redirect (CWE-601).** CWE defines it as accepting "user-controlled input that specifies a link to an external site and uses that link in a redirect"; black-box tools "that supply URLs to every input may be able to spot Location header modifications" [7]. In Playwright: for each URL parameter whose value looks like a URL/path (`next`, `redirect`, `return`, `url`, …), navigate with it set to an off-origin canary host and watch `response` events for a 3xx whose `Location` points off-origin, or a final `page.url()` off-origin. Use `page.route` to abort the canary host so nothing leaves the machine. False positives: low (an off-origin redirect to a host Miqyas chose is unambiguous); false negatives: custom JS redirects behind clicks [7]. Needs the parameter list: always-on for parameters seen in visited URLs, plan for the rest.
- **Secrets in the page, URL or storage.** Two tiers. (1) *Known secrets*: the run's configured secret values (already held by `scrub.ts` / `hide`) searched in `page.url()`, DOM text and attribute values, `localStorage`/`sessionStorage` and `context.storageState()` cookies [1]. Exact match, zero false positives, no dependency. (2) *Unknown secrets*: pattern rules such as gitleaks' 222 rules (MIT) [8], e.g. AWS `(?:A3T[A-Z0-9]|AKIA|ASIA|ABIA|ACCA)[A-Z2-7]{16}` with an entropy floor of 3, GitHub `ghp_[0-9a-zA-Z]{36}` [8]. Provider-prefixed rules are low-noise; `generic-api-key` is noisy by design (keyword + 10-150 chars, entropy 3.5) [8] and should be off by default. Copying a handful of MIT rules needs only the MIT notice.
- **Missing auth on a route.** OWASP WSTG's authorization-bypass test accesses protected resources without a valid session and compares [9] (OWASP's page moved during this research; the method is the standard ATHZ-02). In Playwright: record the URLs (and same-origin XHR/fetch GETs) visited by the authenticated run, then open a second `browser.newContext()` with no `storageState` [1] and request each one (`context.request.get` or `page.goto`). Flag where the anonymous response is 2xx and its body/accessible tree matches the authenticated one (not a login page, not a redirect). False positives: public pages that look alike; need the user to say which routes are protected, or a heuristic "auth run saw the user's name / a logout control". Only GETs; never replay mutating requests.

### UI/UX

- **Clipping.** Per element: `scrollWidth > clientWidth` or `scrollHeight > clientHeight` with computed `overflow` not `visible`/`auto`/`scroll` means content is cut [10]; plus `text-overflow: ellipsis` hits; plus ancestors: intersect `getBoundingClientRect()` with each ancestor whose overflow clips, and flag text whose box is partly outside. Fits inside the existing `observe.ts` walk (it already calls `getBoundingClientRect`). False positives: intentional truncation (ellipsis in tables, line-clamp). Report as UI finding with "intentional?" left to the reader or a plan.
- **Spacing and type scale.** Deterministic only against a declared scale: collect computed `font-size`, `line-height`, `margin`/`padding`/`gap` of rendered nodes and flag values outside a project token list. Without tokens, the only model-free signal is "count of distinct values" (outlier detection), which is noisy. Needs config, so plan/config-driven.
- **Contrast without axe.** WCAG defines ratio `(L1+0.05)/(L2+0.05)` over relative luminance, 4.5:1 normal text, 3:1 large (18pt / 14pt bold), not rounded [11]. Computing it from computed `color` and the first opaque ancestor `background-color` is easy; the hard part is what axe already marks *incomplete*: `bgImage`, `bgGradient`, `bgOverlap`, `fgAlpha`, `pseudoContent`, `complexTextShadows`, `elmPartiallyObscured`, … [12]. Re-implementing gives worse coverage than axe for the same false-negative set. Use axe's `color-contrast` instead.
- **RTL mirroring.** Measured boxes from `observe.ts` in the RTL locale: start-aligned items should have `right` near the container's right edge, order of siblings reversed vs LTR. Already filed; no extra dependency. Needs the locale pair, so a plan or a run option.
- **Platform drift Windows vs Mac.** Pixel diffs are wrong here by Playwright's own warning: "Browser rendering can vary based on the host OS, version, settings, hardware" [13]. A model-free diff that tolerates fonts: compare the two runs' accessibility trees (structure, names, roles, states) exactly, and boxes from `ariaSnapshot({ boxes: true })` [2] or `observe.ts` with a tolerance (e.g. ±4 px, or relative order only). Needs two runs and a baseline, so it is a cross-run report, not a per-page check.

### Accessibility

- **axe-core (names, roles, target size, contrast, focus hygiene).** Rules [3]: names `button-name`, `link-name`, `input-button-name`, `label`, `select-name`, `image-alt`, `frame-title`, `aria-command-name`, `aria-input-field-name`, `aria-toggle-field-name`, … (WCAG A); roles `aria-roles`, `aria-required-children`, `aria-required-parent` (A), `aria-allowed-role` (best practice); `color-contrast` (AA), `color-contrast-enhanced` (AAA, off by default); `target-size` (WCAG 2.2 AA, **off by default** "until WCAG 2.2 is more widely adopted") [3]; focus: `tabindex` (positive tabindex), `nested-interactive`, `scrollable-region-focusable`, `focus-order-semantics` (experimental, off by default) [3]. Most of these can return *incomplete* ("needs review") [3][14].
  - **False positives.** Deque's stated goal is "zero false positives (bugs notwithstanding)"; uncertainty goes to `incomplete`, which "require further testing" [14][15]. So: report `violations` as findings, `incomplete` as a separate "needs review" list, never as failures. Automated coverage is "on average 57% of WCAG issues" [15].
  - **Size.** `axe-core@4.14.0`: no dependencies, `axe.min.js` 652,140 bytes (182,575 gzipped), package unpacked 3.4 MB. `@axe-core/playwright@4.14.0`: 48 KB, depends on `axe-core ~4.14.0`, peer `playwright-core >= 1.0.0` (npm registry, measured 2026-11-03).
  - **Runtime.** Not benchmarked in the docs beyond: "performs very well in general", pages over 50K elements "can take over 10 seconds", and `resultTypes: ['violations','incomplete']` cuts work on passes [16]. Measure on Miqyas's own fixtures before making it always-on; scope with `include()`/`withTags()` [17].
  - **Integration.** `@axe-core/playwright` gives `new AxeBuilder({ page }).withTags([...]).analyze()` [17]. Alternatively inject `axe.min.js` with `page.addScriptTag` and call `axe.run` directly (one fewer package). Iframes are scanned by default; open shadow DOM is supported [16].
  - **Licence (MPL-2.0) for a source-available product.** MPL is file-level copyleft: "The copyleft applies to any files containing MPLed code" [18 Q12]; new files with no MPL code are not Modifications and may stay proprietary, and static linking into a larger proprietary work is allowed [18 Q11]. Shipping unmodified axe in Miqyas's distribution only requires telling recipients where the MPL source is [18 Q8] and keeping its notices [18 Q22]. If Miqyas modifies an axe file, that file's source must be made available under MPL [18 Q9-Q10]. Server-only use is not distribution, but JS sent to a client is [18 Q17]; axe injected into the *tested* page runs on the tester's machine, so a CLI that bundles it distributes it. Cost: a NOTICE/third-party file with the source link; no change to Miqyas's own licence. (The FAQ "is not the license"; confirm with counsel before a public release.)
- **Accessibility tree to replace `nameOf`/`roleOf`.**
  - *Playwright `ariaSnapshot`*: `locator.ariaSnapshot({ mode, depth, boxes, timeout })`; YAML `- role "name" [checked|disabled|expanded|level|pressed|selected…]`; `mode: 'ai'` adds element refs like `[ref=e2]` and includes iframes; `boxes: true` (1.60+) appends `[box=x,y,w,h]` [2][19]. This is Playwright's own role/name engine, the same one `getByRole` matches against, so a check written with `getByRole(name)` and the snapshot can never disagree, which `nameOf` cannot promise. Cost: none (in Playwright already), cross-browser. Gaps: no focus state in the YAML attribute list [19], and refs are Playwright's, not Miqyas's `data-miqyas-ref`, so evidence linking needs a mapping step.
  - *CDP `Accessibility.getFullAXTree({ depth, frameId })`*: Chromium's real tree. AXNode has `role`, `chromeRole`, `name` (with sources), `ignored`, `ignoredReasons`, `properties` (including `focusable`, `focused`, `hidden`, `required`, `invalid`, `level`, `checked`, `expanded`…) and `backendDOMNodeId` (protocol JSON, tip-of-tree). The whole domain and these commands are marked **experimental** [20], and `newCDPSession` is "only supported on Chromium-based browsers" [1]. It is what a screen reader gets, and it carries `focused`.
  - Recommendation for the snapshot ticket: move to `ariaSnapshot({ mode: 'ai', boxes: true })` as the source of roles/names; keep the DOM walk only for what it adds (visibility filter, `data-miqyas-ref`, masked values). CDP is the fallback if focus or ignored-reasons are needed, accepting the experimental tag.
- **Focus order.** Press `Tab` N times (`page.keyboard.press('Tab')`) and read `document.activeElement` each time (role, name, box). Detects: keyboard traps (same element twice in a row, or focus never leaving a widget), focus lost to `<body>`, invisible focused element (zero box or off-screen, WCAG 2.4.11/2.4.7 class), order jumping backwards against reading order (box y/x regressions; respect RTL), interactive nodes from the snapshot never reached. No dependency; one key press + one evaluate per stop (tens of ms each). False positives: "backwards" jumps in legitimate layouts (sidebars, modals); traps are near-zero. Adds `focused` to `stateOf` cheaply via `el === document.activeElement`.

## 3. Always-on vs plan-driven

**Always-on findings, reported apart from the ledger** (no plan assertion needed; run on every capture and listed as their own section, never turning a plan step red): console errors and uncaught exceptions; failed requests and ≥400 responses; known secrets in URL/DOM/storage; curated secret patterns; clipping; axe `violations` (with `incomplete` as a needs-review list); focus traps, focus lost to `<body>`, and invisible focused elements; open redirects on parameters already seen in visited URLs.

**Need a plan, config or second run**: XSS by marker (which inputs to fill), the Trusted Types sink map (opt-in, too noisy alone), missing auth (which routes are protected), RTL mirroring (locale pair), spacing/type scale (token list), platform drift (two runs and a baseline), `target-size` (opt-in until WCAG 2.2 is the project's bar, as axe itself does).

**Not worth building**: home-made contrast (axe covers it better with the same limits).
